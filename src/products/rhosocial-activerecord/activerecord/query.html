01 类型即字段 · Operator Overload

运算符就是字段表达。

User.c.age >= 18 不是字符串。.c 是 FieldProxy， >= 触发 __ge__ 重载，返回的是表达式节点。

03 同步即异步 · One API

      
方法名 100% 相同。差异仅 await。

      

        ActiveQuery 与 AsyncActiveQuery 共用同一套 API。
        唯一差异：基类前缀 Async、with → async with、
        for → async for、终止调用前 await。
        方法名不变。
      

      

        

          
SYNC ActiveRecord（同步）

          


with User.transaction():
    user = User(name="Alice")
    user.save()
    for tag in tags:
        Tag(user_id=user.id, name=tag).save()

          

        

        

          
ASYNC AsyncActiveRecord（异步 · 仅加 await 与 async）

          


async with User.transaction():
    user = User(name="Alice")
    await user.save()
    async for tag in tags:
        await Tag(user_id=user.id, name=tag).save()

06 查询封装 · 分层使用

      
业务复用 vs 外部管理。

      

        在 AR 层，复用查询用 Python 的 @classmethod（Rails scope 模式）。
        在后端层，命名查询用于 CLI 管理与外部发现。
        不是错对，是分层。
      

      

        

          
业务里这样写 · 啰嗦

          
把命名查询当 scope 用


# queries/active.py（后端层）
def active_users(dialect):
    return User.query().where(
        User.c.is_active == True
    )

# 业务代码里：
from queries.active import active_users
users = active_users(
    backend.dialect
).all()

          
每次手动传 dialect / 不是模型方法 / IDE 不补全

分层使用

        

        

          
业务复用 · classmethod

          
AR 层 Scope（推荐）


class User(ActiveRecord):
    @classmethod
    def active(cls):
        return cls.query().where(
            cls.c.is_active == True
        )

# 业务代码里：
users = User.active().all()

          
类型推导友好 / 链式继续 / 直接 .all()

        

      

      

        
为什么分层

        

          Named Query 是面向 CLI 与外部管理的可发现资源，
          不是业务代码内部复用查询的工具。业务里复用查询用 @classmethod（Rails scope 模式）；
          命名查询用于 python -m rhosocial.activerecord.backend.impl.sqlite named-query execute <name>
          这类外部入口。两者并不冲突——同一份查询逻辑可以被 Scope 调用，也可以暴露为 Named Query。
