01 · BASIC · A2

最小模型,4 行。

继承 ActiveRecord,声明 __table_name__,定义字段——就是模型。 下面 4 个 tab 分别展示 Python 3.8 / 3.10+ × sync / async 的写法,差异仅在第一行 import 与基类名。

from rhosocial.activerecord import AsyncActiveRecord
from typing import Optional

class User(AsyncActiveRecord):

    id:    Optional[int] = None     # 主键,自增,可空
    name:  str                       # NOT NULL
    email: str
    age:   int  = 0                  # 默认值

# 使用
user = User(name="alice", email="a@x.com")
await user.save()

02 · FIELD TYPES

Python 类型 → SQL 类型,透明映射。

03 · OPTIONAL · DEFAULT · A2

可选与默认值,就用 Pydantic。

AR 不发明 nullable=True——直接用 Optional。 不发明 default_factory——直接用 Pydantic 的 Field(default_factory=...)。 "AR 字段"完全等同于"Pydantic v2 字段",任何 v2 文档里的字段配置都能用。

models.py · 字段配置示例
from pydantic import Field
from datetime import datetime
from uuid import UUID, uuid4
from decimal import Decimal
from typing import Optional

class Order(ActiveRecord):
    __table_name__ = "orders"

    # 主键 - 自增,数据库分配
    id: Optional[int] = None

    # UUID 主键 - Python 端分配,默认值用 default_factory
    public_id: UUID = Field(default_factory=uuid4, frozen=True)

    # 必填字符串,最长 100 字符
    title: str = Field(..., max_length=100)

    # 可选 + 数据库默认
    note: Optional[str] = None

    # 金额 - decimal · 精度 12,2
    amount: Decimal = Field(..., max_digits=12, decimal_places=2)

    # 创建时间 - 服务端 default(数据库默认值)
    created_at: datetime = Field(default_factory=datetime.utcnow)

    # 状态 - 用 Literal 限定枚举,Pydantic 自动验证
    status: Literal["draft", "submitted", "paid", "shipped"] = "draft"

# 实例化时全部字段都被 Pydantic 校验
o = Order(title="book", amount=Decimal("99.99"))
print(o.id)         # None - 还没保存
print(o.public_id)  # UUID('a3b...') - default_factory 已生成
o.save()
print(o.id)         # 1 - 数据库分配后回填
04 · VALIDATORS

验证器,Pydantic v2 原生。

@field_validator / @model_validator / computed_field——AR 完全沿用 Pydantic v2。 AR 只在保存到数据库前多跑一次 Pydantic 校验,确保入库数据合法。

@field_validator · 单字段

字段级校验,可对值做转换或抛错。在赋值/构造时自动触发。
from pydantic import field_validator

class User(ActiveRecord):
    email: str

    @field_validator("email")
    @classmethod
    def _check_email(cls, v: str) -> str:
        if "@" not in v:
            raise ValueError("无效邮箱")
        return v.lower().strip()

@model_validator · 跨字段

整模型级校验,可访问所有字段。mode="after" 在所有字段都校验完后跑。
from pydantic import model_validator

class DateRange(ActiveRecord):
    start: datetime
    end:   datetime

    @model_validator(mode="after")
    def _check_range(self):
        if self.end < self.start:
            raise ValueError("end < start")
        return self

@computed_field · 计算字段

不存数据库,但包含在 model_dump() 输出里。可用于 API 响应。
from pydantic import computed_field

class Order(ActiveRecord):
    qty: int
    unit_price: Decimal

    @computed_field
    @property
    def total(self) -> Decimal:
        return self.qty * self.unit_price

o = Order(qty=3, unit_price=Decimal("9.9"))
print(o.model_dump())  # {qty:3, unit_price:9.9, total:29.7}

Field(...) · 数据库约束

Pydantic 字段约束 (max_length 等) 同时影响 DDL 生成。AR 把它翻译成 VARCHAR(N)、CHECK 等。
class User(ActiveRecord):
    name: str = Field(
        ...,
        min_length=2,
        max_length=50,
    )
    age: int = Field(
        default=0,
        ge=0, le=150,    # DB 端会生成 CHECK 约束
    )
    score: float = Field(
        default=0.0,
        ge=0, le=100,
    )
05 · FIELD PROXY · 入门

字段不只是容器。

AR 字段系统是三层的:Pydantic v2 验证层(本页主题)+ 字段代理层(本节)+ 类型适配器层(fields.html)。 字段代理让你给一个字段挂上"扩展方法"——不是子类,不是装饰器,是Python 描述符协议的标准用法。

STEP 01
声明 proxy=
字段定义时把代理类传给 Field(proxy=...)。AR 把它注册为该字段的描述符。
class Product(ActiveRecord):
    price: Money = Field(
      ..., proxy=MoneyProxy
    )
STEP 02
访问字段
访问 p.price 时返回 proxy 实例,proxy 持有原值。
p = Product(price=Money(99))

p.price             # MoneyProxy 实例
p.price.value       # Money(99) 原值
STEP 03
调代理方法
所有 proxy 上定义的方法都直接可用,IDE 完整补全。
p.price.in_range(0, 100)
p.price.to_usd()
p.price.format("zh_CN")
# 都来自 MoneyProxy 类

06 · INHERITANCE · A8 MRO

继承与 Mixin。

AR 模型完全遵循 Python 的 MRO(方法解析顺序)。下面 A8 时间轴展示一个用了 3 个 Mixin 的模型在 save() 时的方法解析顺序——这跟你写普通 Python 类时一模一样。

models.py · Mixin 组合
from rhosocial.activerecord import ActiveRecord
from rhosocial.activerecord.mixin import TimestampMixin, SoftDeleteMixin, AuditMixin

class Article(TimestampMixin, SoftDeleteMixin, AuditMixin, ActiveRecord):
    __table_name__ = "articles"

    id:    Optional[int] = None
    title: str
    body:  str
    # 每个 Mixin 自动加几个字段:
    #   TimestampMixin → created_at, updated_at
    #   SoftDeleteMixin → deleted_at
    #   AuditMixin → created_by, updated_by

a = Article(title="hi", body="...")
a.save()    # MRO 决定每个 mixin 的 save() 钩子按什么顺序运行
save() 调用时的 MRO 链:
MRO 01
TimestampMixin
填 created_at / updated_at,然后 super().save()
MRO 02
SoftDeleteMixin
检查 deleted_at,允许 save 仍然走
MRO 03
AuditMixin
从 context 取 current_user 填 created_by / updated_by
MRO 04
ActiveRecord.save
真正执行 INSERT / UPDATE 到数据库

每个 Mixin 都调用 super().save(),所以链条按 __mro__ 顺序串起来。 自己写 Mixin 的关键: 永远 return super().save()。

07 · PY 3.8 vs 3.10+

语法差异速查。

Python 3.10+ 的新语法(PEP 604 union 操作符 |、PEP 585 内置泛型)让模型定义更短,但 AR 同时支持两种语法。 项目最低 Python 版本由你的 requires-python 决定,而非 AR。

Python 3.8 写法
from typing import Optional, List, Dict

class User(ActiveRecord):
    id:        Optional[int] = None
    name:      str

    tags:      List[str] = []
    metadata:  Dict[str, str] = {}
    parent:    Optional[int] = None
    score:     Optional[float] = None

    # 必须 import typing.Optional / List / Dict
Python 3.10+ 写法
# 不需要 import typing 模块

class User(ActiveRecord):
    id:        int | None = None     PEP 604
    name:      str

    tags:      list[str] = []        PEP 585
    metadata:  dict[str, str] = {}
    parent:    int | None = None
    score:     float | None = None

    # 等价语义,更简洁
